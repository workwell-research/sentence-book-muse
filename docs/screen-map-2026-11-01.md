## 0. 結論

いまのアプリは「机」「本棚＋レッスン設定」「受信箱＋接続」の3ページに、初回だけの設定・毎日の作業・必要なときだけの道具が混ざって置かれている。利用者が毎日たどる輪は **届く → 確認して仕舞う → 机で練習する → 本棚に残る** の一本だが、その輪が3ページにまたがり、ページごとに見出し・ナビ・呼び名が違う。

整理の軸は **「毎日使うもの」「最初に一度だけのもの」「必要なときだけのもの」を分ける** こと。行き先を **机・本棚・受信箱・設定** の4つに固定し、どの画面も同じヘッダーで行き来できるようにする。説明文は空の状態と設定画面に寄せ、通常の画面からは消す。

### 1.4 利用者の目で見た問題

1. **輪が3ページに割れている。** 「届く」は /connect、「仕舞う」は /connect と /setup の両方、「練習」は /、「残る」は /setup。どこが家なのかが決まっていない。
2. **受信箱が2つある。** /connect の「受信箱」（クラウドから届く）と /setup の「仕分けを待つページ」（貼り付けで受け取る）。利用者にとってはどちらも「まだ仕舞っていないページ」。
3. **本棚が「設定」の中にある。** 毎日見る本棚が、一度しか触らないレッスン設定と同じページに同居している。
4. **設定が6か所に散っている。** 机のテーマ（ヘッダー）、Note Style（インデックス帳）、声（カード）、タイマーの長さ（トレイ）、印刷（Completed Notes）、レッスン設定（/setup）。
5. **インデックス帳の6タブのうち、2つが同じで1つが古い。** My Vocabulary = Review、Topic Index は廃止した関心へのリンク。
6. **説明文が常に出ている。** 各セクションに前置きと注釈が付く（「毎日のレッスンを作るときに、Museが見る設定です。」「ページは、あなたが確認した本にだけ増えていきます。」「このブラウザに進み具合を保存します。」「届ける時間は、Museの予定で決まります。変えたら、Museにも伝えてください。」など）。読み慣れた2日目以降は全部が雑音になる。
7. **初めての人の道が見えない。** 机は見本で開くが、「自分のページで練習するにはどうするか」が机の上にない。/connect に行っても、まずログイン→受信箱をつくる→共有→キーが並び、何が必須で何が任意か分からない。
8. **呼び名が揺れる。** 「本棚へ／本棚で別のページを選ぶ」「受信箱／仕分けを待つページ／届いたページ」「設定／Note Style／机のテーマ」。

## 2. 整理の原則

- **行き先は4つ。** 机・本棚・受信箱・設定。それ以上は増やさない。
- **同じヘッダーを全ページに。** ワードマーク＋4つの行き先（受信箱には未処理の件数）。スマホでは下部に同じ4つ。画面内の「〜へ」「〜に戻る」リンクはヘッダーに任せて減らす。
- **頻度で置き場を決める。** 毎日のものは机・本棚・受信箱。一度だけのものと必要なときだけのものは設定。
- **一度に一つの主役。** 机では書く行、本棚では本、受信箱では届いたページ。付随する道具は折りたたむ。
- **説明は3か所だけ。** 空の状態、初めての一度きりの案内、設定の項目の下。通常の画面に常設の注釈を置かない。
- **呼び名を固定する。** 本棚／本／ページ／受信箱／仕舞う／机で練習する／設定。
- **データと外部URLは変えない。** localStorage のキー、`/oauth/consent`、メール戻り先、Museのガイドに書いた `/connect` は保つ。

### 3.4 初めての人の道筋

1. `/` を開くと見本のページで机が出る。机の「このページ」タブに1行：**「自分のページで練習するには → 受信箱」**。
2. 受信箱は未ログインでも開ける。上に2つの道：**「Museとつなぐ（設定へ）」**と**「貼り付けて受け取る」**。
3. 設定①は上から順に「ログイン → 受信箱をつくる → Museと接続（キーを発行）」の3段で、済んだ段には印が付く。共有する内容の確認は「Museと接続」の中の一手順にする。
4. 届いたページを開く → 仕舞う → 「机で練習する」。
5. 2日目以降はヘッダーの受信箱の件数が入口になる。

### 3.5 文言の方針

- 常設の注釈を消す。残す場合は `<details>` か設定の項目の下。
- 「このブラウザに保存します」の類は設定④に一度だけ書く。
- 見出しは名詞一語（本棚／受信箱／設定）。前置きの文（「〜する設定です。」）は書かない。
- 空の状態だけ一文の案内（例：受信箱「まだ届いていません。Museとつなぐか、貼り付けて受け取れます。」）。
- ボタンは動詞で統一：開く／仕舞う／使わない／机で練習する／保存する。

## 5. 守ること・リスク

- localStorage のキー（`sentence-book-muse:*`）、ページID、Copy と練習の記録は変えない。
- `/oauth/consent` の経路と `authorization_id`、メールログインの戻り先、Muse側ガイドに書いた `/connect` は変えない（転送で受ける）。
- 受信箱の「開いた端末で仕舞い、ほかの端末からも消える」挙動（receipt）はそのまま。
- `inboxFirst` のような状態で順番を変える仕組みは、分割後は不要になるので消す。
- テスト217件のうち DOM の文言に依存するもの（desk / import / composer）は文言変更で落ちる。文言は最後にまとめて変えて、一度に直す。
- `/handwriting` を外すと `study-page.ts` の7か所の参照の整理が要る。外さないなら今回は触らない。

## 6. 決めてほしいこと

1. **家をどこにするか。** 案は「机が `/`」のまま。初回は見本で開く。代案は「本棚を家にし、机はページを選んでから」。練習を最短で始めたいなら机、毎日のページを選ぶ感覚を重視するなら本棚。
2. **貼り付け取り込みの置き場。** 案は受信箱の中（「受け取る」手段の一つ）。代案は設定の中（「つながらないとき」のまま）。
3. **`/handwriting` を本番から外すか。**
4. **受信箱を未ログインでも開けるようにするか。** 案は開ける（ローカルの仕分け待ちと貼り付けが使えるため）。
