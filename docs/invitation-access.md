# 招待コードによる利用制限

2026-10-30。本人の選択により、教材生成と語句検索は本人・招待者だけが使う。閲覧、保存済み教材の練習、MuseアプリからのJSON貼り付け、ローカルの本棚保存は招待なしでも使える。

## 使い方

`/setup` の教材を作るボタンの上、または机で語句を選んだときに招待コードを入力する。成功すると、そのブラウザで7日間有効。本棚・メモ・履歴は従来どおりブラウザ保存で、招待認証によってクラウド保存や同期は始まらない。「このブラウザでの利用を終了」は認証Cookieだけを消す。

現在は少人数のデモ向けに共通コードを1つ使う。個人アカウントの本人確認・招待者ごとの取り消しではない。コードを知る人は他の人に渡すこともできるため、公開READMEやSNSに掲載しない。漏れた場合はコードと署名キーを交換し、旧デプロイも閉じる。

## サーバーの境界

- `ACCESS_ORIGIN`: 通常の公開URLを完全一致で指定。`wrangler.jsonc` は `https://sentence-book-muse.pages.dev`。hash/branchの別URLでは有料APIと認証APIを403にする。開発用HTTPは明示指定したloopbackだけ許可。
- `INVITE_CODE_SHA256`: 十分にランダムなコードのSHA-256 hex。`SESSION_SECRET`: 別に生成した32バイト以上相当の署名キー。両方を暗号化されたPagesシークレットとして保存する。ブラウザへ渡さない。
- HMAC-SHA256で署名した7日間のCookie。公開時は `__Host-`、Secure、HttpOnly、SameSite=Strict、Path=/、Domainなし。署名対象に公開originと招待コードのhashを含め、どちらの秘密設定の変更でも既存セッションが無効になる。招待コードやCookieをlocalStorage・URL・ログへ保存しない。
- 両有料APIは本文・カウンター・モデル呼出の前に署名と期限を検証。認証なし401、origin/公開host違い403、JSON以外415、設定不足503。認証状態GETはno-storeで返す。
- 招待コードの試行もD1でIPごと5回/分・30回/日、全体500回/日に制限。D1エラーならログインも生成も503。既存の生成3/分・20/日・全体300/日、検索20/分・150/日・全体3,000/日は維持。生成の再試行も1回分を使う。枠の1日はUTC境界（日本時間09:00）で、金額による上限ではない。
- JSON本文は読み取り中にバイト数を数えて上限で中断する。Content-Lengthや文字数だけに頼らない。

## 発行・交換

初回は `node scripts/create-invite.mjs`、交換は `node scripts/create-invite.mjs --rotate`。新しいコードを `.invite-code.txt`、hashと署名キーを `.dev.vars` に保存する（両方gitignore・0600）。実行時に値は表示しない。既存のMetaキーなど他の設定は保持する。コードファイルを本人が確認し、招待したい人へ個別に渡す。

**ローカルで発行するだけでは本番に反映されない。** `.dev.vars` のうち `INVITE_CODE_SHA256` と `SESSION_SECRET` だけを、標準入力経由で `wrangler pages secret bulk --project-name sentence-book-muse` に渡す。ファイル全体を送ると開発用のoriginやモデル接続先も本番へ入るので送らない。秘密値をコマンド引数・チャットへ貼らない。続いてbuild/deployし、未認証401・招待確認成功・認証済み動作・logoutを確認する。

過去のPagesデプロイは過去のコードと秘密設定を保持するため、交換後も残すと旧認証が使える可能性がある。新しい本番の確認後、deployment listで対象を照合し、不要な旧deploymentをdeleteする。最新の本番は残す。過去コード自体はGitに残るが、脆弱な版へそのままrollbackしない。

## 検証

`npm test` は署名改ざん・期限切れ・二重Cookie・鍵交換・匿名呼出・CSRF・別host・D1障害・再試行上限・本文バイト上限を確認する。`scripts/qa-invite.mjs` はloopbackの独立Pagesサーバーと模型モデル専用。`tests/support/access.ts` の固定コードはテスト用で、本番のコードではない。実キーや本番URLでこのQAを実行しない。

ブラウザ検証用originの例は `http://127.0.0.1:8801`。ローカル `.dev.vars` の `ACCESS_ORIGIN` を一致させる。模型モデルの接続先・キーは別に用意し、実APIに接続しない。通常のViteサーバー単独には認証APIがないので、生成と検索は利用確認待ちになるが、練習やローカル保存は使える。
